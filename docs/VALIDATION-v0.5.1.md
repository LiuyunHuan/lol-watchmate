# v0.5.1 死亡误触发与五秒冷却修复

2026-10-24。用户报告 Heng 击杀 TheShy 却被开串、Meiko 一次死亡多次开串且有迟到消息。本次只修死亡判断与输出调度，保留 v0.5 手动虎扑搜梗、语音优先级、保护规则和十秒云端截图策略；无新增付费服务。

## 发现与修复

旧版为了减少漏报，原始 KDA 数字一增长就发事件，显示区却使用稳定过滤；因此显示正确不代表触发过程没有瞬时误读。旧检测器还把冷却内的证据放入 pending，随后无新死亡也能补发。弹幕生成有另一条消息入口，迟到内容也能进入文字板。

当前截图只有应用界面，没有该次击杀的原始比赛帧或当时的逐帧识别数据，**不能确定 Heng 这一次具体是哪一块像素/OCR 误读**。代码中可复现的误触发路径和延迟补发路径已修复，并建立回归；不得把模拟事件测试说成重放了这次比赛片段。

| 位置 | 当前处理 |
| --- | --- |
| `src/core/broadcast-detector.ts` | KDA 死亡计数增加必须在五秒内两次不同采样确认；单次错读后恢复不触发。首次数字仅建基线，杀人数增加不是死亡。 |
| 同一死亡的证据合并 | 头像/击杀栏触发后记录尚待计数确认的死亡；后来的 KDA 增加抵扣该记录，超过五秒也不因此补一句。反向先由 KDA 确认时也锁存死亡状态。 |
| `src/ui/broadcast-vision.ts` | 对线计分板绿色生命条是明确存活证据，阻止灰色皮肤/头像被数字 OCR 判成死亡；计时回退 OCR 要求置信度至少70及对应白色字形数。 |
| 击杀栏 | 保留原本右侧受害者裁切；绑定选手必须唯一。同帧明确存活时不让击杀栏匹配覆盖存活证据。无计分板继续只读可见击杀栏。 |
| `electron/engine.ts` | 所有个人梗在生成文字和排队语音之前共享五秒门槛，包括手动模式、重置检测后事件、弹幕延伸。按系列赛、小局、归一化选手名计时，不是全局冷却；其他选手可正常触发。 |
| 重复与迟到 | 冷却内信号消耗后直接丢弃，不存在待补播列表；迟到弹幕结果丢弃。既有回答优先、用户打断、语音过期机制保留。 |

仍允许回放开串；不恢复旧版严格回放封锁。五秒是触发间隔，不是“每五秒必播一次”，持续同一死亡画面不会反复触发。仅靠 KDA 的事件会增加一次统计采样确认延迟，明确头像死亡不等待该确认。
