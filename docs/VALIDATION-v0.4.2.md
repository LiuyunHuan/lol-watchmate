# v0.4.2：死亡开串优先减少漏报

2026-10-23。用户明确变更需求：回放也可以玩梗，头像变黑/死亡状态与死亡数增长都能作为信号，接受同一死亡输出不同短句，宁可多发，不接受大量漏发。本更新覆盖旧版严格回放过滤、首次接入不触发和多证据强制合并规则。

## 原因与行为变化

用户截图可见本地识别耗时4607ms。v0.4.1左侧选手信息允许15秒内的本地结果，死亡触发器却只接受3.5秒内结果；超过4秒的采样间隔又会清掉存活基线，导致“左边已经显示死亡，右边没开串”。此外仍有回放、时间倒退、时钟静止、双帧确认和语音按截图时刻过期等拦截。

当前行为：

- 自动和手动本地事件统一使用 `BroadcastDetector`；接受15秒内的当前采集结果，旧窗口/取消请求、过时或重复时间戳仍拒绝。
- 明确头像死亡、原始本地KDA死亡数增加、新击杀栏受害者独立触发。玩梗不等待用于统计UI的两次确认；等级/KDA显示仍保留原稳定过滤。
- 首次看到死亡头像可以说；首次只有历史累计死亡数、没有头像或击杀证据则只记基准，不把整场历史死亡补播。
- 回放、倒退和大幅跳进度视为新片段，允许再次说；不再等待时钟追上原来的最高值。时钟不可读或冻结也不拦截明确头像死亡。
- 静止的同一头像、相同KDA或持续击杀栏不逐帧刷屏。每个选手新信号之间至少1.5秒，期间的新信号保留待处理。头像触发后KDA增长可以再说一句。
- 多条可用梗时避开该选手刚说过的句子；只有一条启用内容时仍可能重复。团战继续优先一位明星加团队梗。
- 待播8秒从进入语音队列开始算，避免慢识别刚到就过期；延迟统计仍用原截图时间，不粉饰真实延迟。用户讲话、正经回答、保护与暂停规则保留。
- 手动模式中匹配的灰头像不再强求OCR读出死亡倒计时。自动识别的像素算法没有修改；识别不到任何信号时仍可能漏报，不承诺所有死亡100%捕捉。

## 验证

- TypeScript、构建、64项规则测试通过。旧版严格回放拒绝/两帧要求的测试按本次用户新要求改写，新增或覆盖慢帧、独立信号、冻结时钟、回放/跳转、首帧死亡、短冷却保留新证据、保护/暂停等场景。
- 打包程序 `test:death-trigger` 通过实际IPC与Windows SAPI播放：原稀疏KDA多人死亡场景成功；新增4607ms慢头像、从500秒倒退到208秒的回放场景成功；后续KDA增加又产生另一句，并实际起播。报告 `artifacts/death-trigger-v0.4.2.json`。
- 打包桌面冒烟通过：语音、问答演示、费用/暂停、系列赛、梗库开关、设置。测试中发现复选框的 `uncheck()` 会在主进程异步确认前断言，已改为实际点击后等待应用状态并核对复选框，重跑通过。
- 打包 `test:local` 通过真实Windows测试窗口采集、手动框选、离线OCR、灰头像触发、SAPI起播、英文/中文回放标识及倒退后继续开串、暂停停止；没有外部OCR请求。合成测试画面本次起播指标约945ms，仅代表该测试，不是实际比赛三秒证明。报告 `artifacts/local-smoke.json`。

这些是构造事件序列/测试画面的验证，不是用户整场视频重测。没有使用用户付费API；本地测试网络使用模拟服务。没有重新跑完整11图像素回归，也没有改变既有图片识别真值。更多误报和重复是本次优先减少漏报的明确取舍；没有宣称3秒或每小时5元目标已达成。
