## 用户现在要什么

用户不满意搜索摘要里的泛泛句子。只用虎扑公开帖子、比赛讨论和可读评论理解选手梗；不再采集贴吧。ShowMaker S1–S3、knight K1–K3 是先前人工整理、用户认可的语气参考，并非真实 Qwen 已生成的结果，也不能硬编码为生产搜梗答案。要短、有辨识度、能在死亡后播报，可基于真实梗改写。

用户确定取消所有自动搜梗，只允许手动选择名单后启动；盾牌保护默认不选，明星重点搜索，选择不改盾牌。搜到先进候选区，用户挑选后才启用；梗库提供手动增删改和撤销。

原三秒死亡目标不改变：准备时可付费检索/整理，现场死亡不等候新搜索或完整战术分析。用户说话 > 正经回答 > 玩梗。后台截图仍默认十秒，本地检测仍每 500ms 尝试，忙则跳过。

## 数据与兼容

继续使用原应用数据目录，不重置用户历史。`memes.json` 同时保存已入库、待审和已删除内容：`review` 为 approved / pending / deleted，旧条目默认 approved，保留旧 enabled；首次分配 UUID 并持久化。删除记录仍保留，可撤销，同时阻止下次搜索或导入补回相同内容。编辑产生旧文本墓碑，阻止旧待播句继续播放。

候选附 `evidence`：连续原文摘录、解释、评论 ID、点赞（未知为 null）、日期、改写标记、引用上下文。`sources` 由已采集文档产生。没有可核对的原文、时间或对象锚点的输出丢弃。生成模型仍可能误解，所以审核不可省略。

旧 `searchKey` / `searchUrl` / `searchRate` / `autoLearn` 兼容解析，但不产生旧搜索请求。`qwenSearchRate`、`searchInputRate`、`searchOutputRate` 是新的独立费率，默认 null；不把旧博查价格当成 Qwen 价格。一个搜索调用会产生模型和工具两条费用记录，界面不能把记录条数当 HTTP 请求数。百炼插件 count 是意图次数而非账单次数，工具状态保持待核对。

## 已知限制与必须继续的验证

1. **真实 Qwen 链路尚未完成。** 2026-10-24 隔离进程解密现有凭据失败，没有请求付费模型；用户明确回复“暂时不方便，先完成其他验证”。不要重新追问同一许可，也不要宣称 S1–S3/K1–K3 已被真实服务复现。用户方便时在实际程序设置重新保存百炼凭据，再运行两位选手的手动搜索；必须人工核对对象、原文、条件和笑点。
2. 评分讨论帖可读取。发现 App 入口不会启动 App；发现允许域名上的实际 HTTPS 评分入口会做有限访问，但尚无验证过的独立评分数据解析器，仍明确提示“评分页未读取”。不应对外宣称支持全部虎扑评分热评。
3. 仅支持已验证公开页面结构和 bbs 数字帖子路径。移动/voice 页面、搜索覆盖、登录墙、不同评论结构可能没有候选。不要为了凑数量退回虚构来源或自动导入。
4. 当前特殊条件只支持普通死亡与四位队友明确存活；中路位置、击杀者、特定装备等一律 manual-only。编辑面板允许用户确认适用条件；`safeCondition` 对明显的未支持场景强制 manual-only，四位队友存活需要相应证据。可以另建明确适用的手写句子，但不要偷偷在现场增加付费判断。
5. 本轮没有重新跑整场比赛，也没有重新修改英雄/数字识别算法或图片真值。原有三秒、每小时五元目标仍没有整场测量证明。
6. 安装包未签名、未发布到 GitHub、未覆盖用户原安装。应区分安装包构建/内容检查、解包程序测试和真实安装向导执行。

## 下一步验证操作

从源码用 Node 22.12+。运行 `npm run check`、`npm test`、`npm run build`；`npm run test:memes` 是模拟链路；`npm run test:hupu` 是无登录公开页面真实采集；`npm run test:hupu:live` 会用当前本机已保存凭据产生有限真实请求，仅在用户准备好凭据后运行。绝不把密钥放进源码、聊天、报告或完整复制个人数据到测试目录。

配置好后，在梗库添加 ShowMaker 与 knight，截止日期选录像赛前，先普通搜索。核对原文来源、评论对象和条件，记录每名选手候选数、失败原因和实际账单；无结果继续改进检索/清洗，不能写固定候选。`artifacts/` 是本机验证输出，不进入发布包或公开仓库。
