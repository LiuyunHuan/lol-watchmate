# 初版测试手册

## 自动检查

```powershell
npm run check
npm test
npm run build
npm run test:desktop
npm run test:capture
npm run test:local
```

单元与状态集成测试不调用付费服务。桌面冒烟启动真实 Electron、操作界面、调用本机中文语音并静音播放，同时使用独立的 `.smoke-data/`。截图和报告在 `artifacts/`；这些目录不会进入 Git。

`test:capture` 会打开本程序创建的合成测试窗口，通过真正的 Windows 窗口采集送到本机模拟服务，检查背景识别、问答、ASR、页面切换与暂停链路，并确认云端结果不再触发死亡。它不采集用户已有窗口，也不访问付费云端。

`test:local` 使用合成的彩色/灰色头像和数字，通过真实窗口采集、手动校准界面、随包离线OCR、死亡检测器和实际语音播放回执，检查完整本地链路。另覆盖中英文回放标识、时钟倒退、提问新截图、暂停与无OCR外网请求。设置 `WATCHMATE_EXECUTABLE` 为打包后 exe 的绝对路径，可检查随包资源。模拟结果不能替代真实赛事识别验证。

## 第一次试用：不用密钥

1. 体验演示 → 选手死亡：文字板出现 TheShy 梗，并听到语音。
2. 保护 TheShy → 再触发死亡：不再生成他的梗。
3. 解除保护 → 多人团战：一条个人梗后跟一条团队梗，不逐个念五个人。
4. 关闭蓝方团队梗 → 多人团战：个人梗仍允许，团队梗消失。
5. 输入一个问题并立即触发死亡：文字可同时出现，语音分析优先。
6. 模拟回放：允许再次开串，同一静止信号不逐帧刷屏（v0.4.2规则）。
7. 费用提醒 → 暂停 Agent：停止语音，文字保留。
8. 结束本局 → 系列赛：文档应有十位选手，每人一行。
9. 下一局 → 开始演示 → 把 TheShy 的英雄改为剑姬：触发“上把扛压，这把亮剑”。
10. 手动向上滚动文字板后触发新消息：不应把阅读位置拉回底部。

## 第二次试用：真实窗口与自备密钥

先用熟悉的比赛回放，确认版本、选手ID和音频设备，再测直播。开启“用量”页记录识别次数和费用。

重点观察：

| 场景 | 记录内容 |
| --- | --- |
| BP | 十人身份、英雄、位置有没有串位；更正后是否被覆盖 |
| 单人死亡 | 漏识别、认错人、重复次数；触发证据是否合理 |
| 团战 | 是否优先吐槽预期选手；批次是否切得过碎 |
| 回放 | 有/无回放字样时是否误触发 |
| 麦克风 | 是否误把解说当成提问；打断是否及时 |
| 战术问答 | 是否具体，是否说明条件，是否编造版本强度或统计 |
| 搜索 | 来源能否打开、样本范围是否清楚；查不到是否承认 |
| 偏好 | 选手换边后保护是否仍跟着ID；团队开关是否独立 |
| 暂停 | 是否停止新模型请求、截图处理、录音与语音 |
| 长时间使用 | 文字回看、窗口切换、网络恢复、费用记录是否正常 |

“用量 → 导出测试记录”保存指标和事件时间，不包含密钥和问答正文。主观反馈可另写 `docs/FEEDBACK.example.md` 的格式。

## 延迟口径

目标：语音空闲时，从共享画面首次可辨认的死亡证据，到常用梗实际开始发声，控制在3秒内。

当前自动指标的起点是**首个被本地检测器采用的证据帧采集时间**，不包含它之前最多约0.5秒的采样等待，也不是现实赛场时间。完整目标应通过录屏同时观察“本地播放画面”和“搭子发声”来人工复核。慢机、OCR初始化、多人死亡或语音未预热仍可能超标。

演示事件的延迟只用于检查队列与音频，不能作为实际画面识别性能。问答占用期间被抑制或丢弃的梗要单列，不混进空闲链路统计。

不预设“准确率达到某数字”或“梗一定好笑”的验收结果，交由使用者完成第一轮试用后定义。

## v0.3 原图与窗口回归

自行提供三张图 `scoreboard.png`（1920×1200）、`compact.png`（1920×1200）和 `bp.png`（1782×1049应用预览），设置 `WATCHMATE_FIXTURES` 为所在目录，运行 `npm run test:broadcast`。这些测试图属于用户素材，不随仓库发布。BP图的比赛区域在脚本中显式框选；游戏图排除顶部/底部黑边后为1920×1080。

断言包括两个游戏时钟、十人ID、团战十英雄、死亡位置和倒计时、指定KDA及等级、击杀栏过滤目标物、BP接受的英雄无错认。之后将识别结果送进真实IPC、事件编排和本地语音；存活到死亡的时间序列是人工构造，不能冒充原始录像的准确率/延迟。

`node scripts/broadcast-capture.mjs` 将两张游戏原图放在独立测试窗口，再通过正常选择窗口流程采集，验证实际渲染器中的自动识别，不替换识别代码。仅调用本机模拟云端服务。两项脚本都支持 `WATCHMATE_EXECUTABLE` 指向打包后的应用；报告保存在 `artifacts/`。

真实使用时，先确认上方“自动识别”已显示正确布局与选手。无需勾选“使用手动校准模式”。屏幕有其他边栏时调整完整比赛区域。第一次接入已死亡不会吐槽，应在后续真实死亡或人工测试序列检查触发。
## v0.5 手动搜梗

- `npm run test:memes`：隔离数据目录，真实桌面 + 模拟搜索/模型/页面。覆盖保护选手默认不选、明星重点搜索、候选审核、增改删/撤销/启停/筛选/重启。不是付费模型测试。
- `npm run test:hupu`：真实读取四个公开虎扑参考页，检查预期评论、日期、热评和引用；无需登录或 API Key。输出 `artifacts/hupu-public-pages-only-v0.5.json`。
- `npm run test:hupu:live`：显式请求真实 Qwen 搜索和整理，每位 ShowMaker / knight 使用普通预算上限；使用已有系统加密凭据，绝不复制或输出配置。凭据不可用或两位选手未均生成候选会失败。当前真实验证已按用户选择暂缓，不能把模拟链路通过算成它通过。
- `WATCHMATE_EXECUTABLE` 可指定解包后的 exe 跑桌面回归；测试不覆盖原用户安装、也不读其观赛数据。
- 核对原文、评论对象、热度、时间范围、改写与适用条件。评分 App 页面不可读时应明确提示，讨论帖不能假称评分页全量热评。
