顺序回归从 BP 开始，经无计分板、对线、团战切换。完整 BP 阵容仅用于候选约束；进入游戏后，同队四个位置确认且仅剩一位被遮挡时，可排除确认最后一位，结果明确标记来源。没有从 BP 的展示顺序直接绑定选手。

首次单独打开灰头像或变体遮挡的图片，仍可能出现待确认。例如 14:04 单图首次读取只接受 8 个英雄；同场顺序读取可保留完整 10 人。这与把该图片单独识别成 10 个英雄不同。首次进入时不补播已经发生的死亡。

## 字形训练与验证边界

`public/hud-font.json` 是字符形状库。训练脚本只提取数字和斜杠/冒号的小字形，不保存选手、图片编号到答案的映射；它与英雄原画特征匹配相互独立。训练包含部分上述样本以及通用缩放增强。因此“提供图片的回归通过”不能当作独立测试集准确率。

22:35 团战图和浏览器 12:13 图未用于字形提取，可检查相同转播字体下的泛化。尚未覆盖所有未来 KDA 数字组合、转播字体和皮肤；未知字形由 OCR 尝试，低置信度保留待确认，数字经过两次观测及时间一致性过滤。

## 性能和费用

本机这一轮顺序回归：首次 BP 特征匹配约 15 秒；进入游戏并建立阵容后，含统计字段的图片处理约 0.45～1.42 秒。热缓存的三次死亡检测约 302 / 325 / 306 毫秒。首次图库和 OCR 准备另需时间，冷启动单图全英雄匹配比热缓存慢。

这些是软件处理固定图片的耗时，不包括采样等待、事件聚合和语音起播，不证明实际整场比赛三秒达标。动态语音触发另以构造的存活→死亡序列检查 IPC、去重、文字及本地语音回执，不能冒充连续录像的准确率统计。

新增识别全部本地运行，没有每秒计费视频模型。仍保留原有的每 10 秒一张背景云端截图、用户提问另取新截图；这两类云端请求会按用户服务商计费。自动本地模式每 500ms 尝试检测，忙时跳过；数字统计约每 2 秒更新，身份稳定后使用缓存。

## 梗库与搜索

- 贴吧检索为空时，最多补查一次历史网页资料；接口结构错误不再伪装成“没有搜到”。
- 接受兼容的网页列表结构，明确日期晚于截止日的来源继续排除。
- 整理得到的梗立即去重写入 `memes.json`，重启后复用；已有缓存的选手不自动重复搜索。
- 旧版隐藏的通用死亡短句改为梗库里的可见条目，可关闭；专属梗仍优先。Wei 的那句“先躺一会儿，队友还在上班”来自内置通用短句，不是现场搜到的选手梗。
- 相关响应解析、空结果回退、重启复用、开关持久化采用模拟 HTTP 响应测试。本轮没有再次访问用户的真实付费账户，因此不声称账户余额或服务权限问题已修复。

## 复现

```powershell
npm run check
npm test
npm run build
npm run test:recognition
npm run test:broadcast
npm run test:desktop
npm run test:broadcast-capture
```

`WATCHMATE_FIXTURES` 可指定自有目录，以 `bpfull.png`、`scene.png`、`newscore.png`、`scoreboard.png`、`scoreboard2.png`、`compact.png`、`compact2.png`、`observed1.png` 至 `observed4.png` 命名。没有原图时不生成或伪造测试通过记录。设置 `WATCHMATE_EXECUTABLE` 为打包后 exe 路径，可复验随包资源和应用链路。

可视核对报告由 `node scripts/recognition-review.mjs` 生成到 `artifacts/recognition-review.html`，展示原图、实际裁切区域、人工值和软件输出；完整机器输出位于 `artifacts/recognition-regression.json`。
