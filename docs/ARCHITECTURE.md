# 实现结构

## 运行边界

Electron 主进程持有应用状态、配置密钥、网络请求、数据存储和本地语音缓存。渲染进程仅通过固定 IPC 桥访问这些能力，不开放 Node、任意文件读写或任意 shell。所有 IPC 校验调用窗口和输入结构；主窗口拒绝网页导航和新窗口，外部来源经协议白名单交给系统浏览器打开。

本地文件保存到 `app.getPath('userData')`，不依赖源码目录可写。测试通过 `WATCHMATE_DATA_DIR` 隔离数据。`WATCHMATE_DEV_URL` 只接受固定的本机开发地址。

## 数据流

```text
选定窗口 → getDisplayMedia ┬→ 每10秒JPEG → 云端视觉 → 比赛背景（不触发死亡）
                         ├→ 每0.5秒本地图块 → 英雄图库+离线OCR → BroadcastDetector / 备用 LocalDeathDetector
                         │                                      ↓
                         │                    去重/屏蔽/明星排序 → 已缓存的梗与语音
                         └→ 提问即时截图 → 优先云端视觉 → 当次问题场景

麦克风 → 本地VAD → 16kHz WAV → ASR → 用户提问
                                        ↓
                     历史检索 + 当前阵容 + BO5 Markdown → 正经回答
                                                        ↓
                                              文字详情 + 语音结论

SpeechQueue → Windows SAPI / WAV缓存 → Audio播放 → 实际起播回执
```

## 核心接口

共享类型集中在 `src/shared/types.ts`。

- `Observation`：当前画面阶段、游戏计时、十个位置的身份/英雄/死亡状态、置信度、证据、可见弹幕。无证据时允许 `null`，不把未知当作零。
- `DeathEvent`：系列赛/小局、位置、游戏时间、证据采集时间、检测时间、事件来源。选手屏蔽在事件触发前应用。
- `Message`：用户、分析、玩梗、系统通知四类，带来源、游戏时间、关联对象、引用和语音状态。
- `SpeechJob`：回答或玩梗，目标对象、过期时间、实际语音状态；语音和文字相互独立。
- `UsageRecord`：模型、类别、请求时间、输入输出用量、音频时长、估算费用及用量可信状态。

## 状态与并发

- 主进程是唯一状态源，渲染器订阅快照。
- 视觉请求单飞，避免网络慢时无限积压。改变采集窗口会使旧窗口识别结果失效。
- 模型请求超时默认60秒，设置可调；百炼搜索使用同一配置超时，虎扑页面15秒。视觉临时故障指数退避5～60秒，配置/鉴权类HTTP错误停止自动视觉请求直到重新开始。服务错误只展示状态、来源和已知错误码，不回显任意上游错误正文。
- 暂停、换局、换系列赛会递增运行代次，并取消网络请求和本地合成进程；返回的旧结果不进入新状态。
- 费用回执可以在暂停后继续写入：取消不等于服务端未计费。
- 新问题使旧问题的结果失效。用户开口会停止正在播放的音频；正经回答完成前，玩梗只进入文字与待播队列。
- 选手偏好以规范化 ID 为键保存于当前系列赛运行状态，换边时迁移到新位置。
- 团战聚合窗口本地检测650ms、演示450ms；同一选手在批次中只记一次。过期梗保留文字，待播队列不无限增长。

## 死亡与回放

v0.4 默认使用 `src/ui/broadcast-vision.ts` 和 `champion-vision.ts`：将比赛区域归一到1920×1080，区分 BP、对线计分板、团战横排和无计分板局内画面。BP 使用本地多尺度特征与空间一致性匹配；局内头像用官方图库、有限变体及本局缓存。BP 展示位与选手位置分开，完整阵容仅约束候选；同队其余四位已识别时可以排除确认最后一位，并标记依据。没有计分板时不更新选手统计，只处理时钟、回放和击杀栏。

`hud-glyphs.ts` 在各字段单独裁切区域提取中性白色字形，分别匹配时钟、等级、横排等级、KDA 和死亡计时；不确定时回退离线 OCR。多个阈值必须保留完整数字，防止 14 被删成 1。`ScoreboardStats` 对显示数字做稳定过滤。v0.5.1 的 `BroadcastDetector` 对原始死亡计数单独做两次确认，不串联显示过滤增加额外延迟；明确头像仍即时触发，死亡计数抵扣已报告头像/击杀栏事件。计分板绿色生命条否决灰色脸的死亡 OCR；击杀栏只匹配右侧受害者，并要求英雄绑定唯一、不与明确存活矛盾。检测器与主进程输出端均有每人五秒冷却，冷却内信号消耗后丢弃，没有待补播队列。主进程按系列赛、小局和归一化选手身份计时，重新检测/换窗口/暂停不绕过输出冷却。仍接受15秒内本地结果和回放。

回放、倒退、前跳视为新的可见片段，不保留阻止事件的历史最高时钟；时钟冻结或不可读也不拦截明确死亡。首次看到已死亡头像可以触发。头像状态、KDA最高值、当前击杀栏分别记忆，防止同一静止证据不断刷屏；同一选手新信号间隔至少1.5秒，期间新信号等待而不丢弃。头像触发后KDA再涨可以接第二句；有多条可用梗时避开上一句。梗的待播期限从事件入队开始计8秒，采样时刻仍用于真实延迟计量；用户说话和回答优先级不变。

备用模式的前提是用户框选游戏时钟和存活头像，绑定已确认的选手身份。`src/ui/local-vision.ts` 在隔离的本地WASM Worker识别时钟、候选死亡倒计时与可选回放标识；Tesseract.js和中英文模型随包提供。IPC只传有限的数值特征/识别结果，不传本地原始图块。保护选手不进行倒计时OCR。

主进程的`LocalDeathDetector`检查校准ID、时间戳、头像边缘相关性和相对去色程度。匹配灰头像即为证据，不强求读到倒计时；事件委托同一个`BroadcastDetector`，手动与自动模式均允许回放开串。身份不符、转场、重复时间戳和超过15秒结果仍丢弃。自动布局未识别、也没有手动校准时，不会用云端结果触发死亡。旧`DeathDetector`仍有历史规则测试，但不再承担手动或自动本地死亡事件链。

结构/颜色阈值是可测试启发式，不是已训练的LOL通用检测模型；不支持所有转播布局。多个头像的OCR在单张本地合成图中处理，忙时跳帧。3秒验证需实际录像、真实机型和已预热语音，不能只凭单次合成测试宣称达标。

提问通过`questionFrameRequest`请求渲染器即时截取已授权窗口；请求ID和时间戳防止复用旧图。提问递增视觉代次并取消旧周期视觉，周期视觉在问答期间让位。截图获取超时5秒，模型请求沿用配置超时，失败后向问答模型明确传入信息缺口。取消的付费请求仍可能计费。

## 模型与检索适配

`electron/providers.ts` 通过 `fetch` 调用兼容 Chat Completions 的百炼文本/视觉/ASR接口，以及同密钥的 DashScope 原生联网搜索。ASR 使用 `input_audio.data` 的 WAV Data URI，按 `usage.seconds` 计费；文本/视觉按服务返回 token 计费。没有用量、费率或中断的请求标为未知。

JSON 输出经 Zod 校验，拒绝同一画面重复位置。自由文本不进入 HTML，模型输出和 Markdown 都按纯文本渲染。检索来源、可见弹幕只作为数据；不能触发工具调用或替换系统规则。

版本/历史检索是有边界的检索增强，不是联网自动驾驶。默认搜索截止到系列赛开始前一天，丢弃明确晚于截止日期的结果；历史检索不更改正在观看的比分或死亡状态。没有日期的结果仍可能有风险，README 已列明防剧透限制。

## 可替换点

后续可在不改变文字板与状态规则的情况下替换视觉检测、语音识别、TTS和历史数据来源。替换时必须保留取消语义、费用回执、来源标记以及实际起播回执。

## v0.5 手动搜梗路径

`MemeLibrary → meme-search IPC → Engine.preparation → Providers.search（真实来源元数据） → HupuReader（公开正文/评论） → Qwen整理 → validateCandidates → memes.json pending → 用户审核 → approved → selectBanter`。

观看 running 与搜索 preparation 是不同状态：未观赛可搜，搜梗不申请窗口或麦克风。全局暂停取消两个 Provider 实例和页面 AbortSignal；搜索返回还需匹配当前任务对象。费用回执允许在取消后补记，候选不接受迟到结果。

`meme-review` 支持批量 approve/delete/restore；`meme-save` 新建/编辑；`meme-toggle` 启停。全都按 UUID 操作，旧库加载时迁移，保留原 enabled。删除记录是持久化墓碑；编辑旧句也留下墓碑，以阻止旧队列继续说。受条件限制的梗通过 `playable/safeCondition` 统一过滤，不发现场模型请求判断条件。详细边界见 [v0.5接续说明](HANDOFF-v0.5.md)。
