# LOL 观赛搭子 · Watchmate

认真聊比赛，适时开个串。

维护交接（2026-10-24）：新环境先看 [接手入口](docs/DEEPSEEK_START_HERE.md)、[完整交接文档](docs/HANDOFF.md) 与根 [维护约定](AGENTS.md)。包含需求沿革、完成度、验证边界和私有测试图片迁移方法。

一个本地运行的 Windows 桌面观赛伴侣。你在 B站打开比赛，选中直播窗口，搭子通过画面了解比赛；你问 BP 和赢法时认真回答，选手死亡时从梗库中接一句。**文字详细，语音讲重点。**

> v0.5.1：修复死亡误触发路径，同一选手五秒内最多开串一次，重复信号丢弃、不延后补播。保留 v0.5 的手动虎扑搜梗与候选审核。见 [死亡修复验证](docs/VALIDATION-v0.5.1.md)。真实 Qwen 验收暂未完成，见 [v0.5 验证报告](docs/VALIDATION-v0.5.md)；真实比赛三秒响应与每小时五元仍是待验证目标。

## 直接体验

打包产物位于 `release/`：

- `LOL-Watchmate-0.5.1-Setup.exe`：Windows 安装程序，含离线 OCR 和 173 位英雄图库。
- `win-unpacked/LOL观赛搭子.exe`：免安装运行（须保留整个文件夹）。

当前安装程序未签名。项目已具备 GitHub 源码与 Windows 构建工作流，尚未创建远程仓库或发布 Release。

进入应用点击 **体验演示**。演示里的选手名单、画面、事件和分析都明确标为演示，不代表真实阵容或赛程，也不调用付费 API。点击“选手死亡 / 多人团战 / 识别回放 / 费用提醒”，可以测试文字、语音及保护开关。

首次语音合成会启动本地语音服务；后续同一句话从缓存播放。需要 Windows 中文语音包。没有音色时会在文字板提示，不会假装已播报。

## 从源码启动

要求：Windows 10/11、**Node.js 22.12+**、npm；无需 Python、独立服务器或数据库。

```powershell
npm ci
npm run dev
```

仓库不包含 Riot 英雄图片（版权原因，见 [第三方组件](docs/THIRD_PARTY.md)）。首次从源码运行或打包前，先用官方接口把图库生成到 `public/champions`：

```powershell
npm run assets:champions -- 16.21.1
npm run assets:champion-variants
```

没有图库时应用仍可启动、可演示，但 LPL 自动识别不可用；安装包在构建时把图库打进 asar，用户端不再下载。

Electron 44 的二进制通过本项目的 `postinstall` 安装。如果下载失败，可在当前 PowerShell 会话设置镜像后重试：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
npm ci
```

开发时修改渲染界面会热更新；修改 `electron/` 或共享核心后重启 `npm run dev`。

```powershell
npm run check        # TypeScript
npm test             # 核心规则、状态编排与服务契约测试，不调用付费服务
npm run build        # 生产构建
npm start            # 启动生产构建
npm run test:memes   # 手动搜梗、候选审核和梗库 CRUD 桌面测试（模拟服务）
npm run test:hupu    # 真实公开虎扑页面采集；不使用模型密钥
npm run test:desktop # Electron 桌面冒烟；使用独立测试数据目录，静音播放
npm run test:capture # 真窗口采集 + 本机模拟模型，验证整条接口链路
npm run test:local   # 真窗口 + 离线OCR + 校准 + 死亡检测 + 实际语音回执（合成HUD）
npm run test:recognition # 四种布局原图与同场顺序回归；WATCHMATE_FIXTURES 可指定测试图目录
npm run test:broadcast # 原图到 IPC、事件和语音链路回归
npm run pack         # 免安装目录
npm run dist         # Windows NSIS 安装程序
```

## 开始实际观赛

1. 在设置中填写百炼 API 密钥。默认接口是北京地域的兼容接口；密钥、模型权限与地域要一致。也可填写百炼提供的工作空间专属地址。
2. 默认模型为 `qwen-plus`（问答）、`qwen3-vl-plus`（视觉）、`qwen3-asr-flash`（语音识别）。模型名称和接口可修改；更换供应商时需要确认其协议兼容性。
3. 搜梗与战术联网检索共用百炼密钥，默认检索模型 `qwen-plus`。在“梗库 → 搜索梗库”选择选手、重点搜索和资料截止日期；不需要先开始观赛。搜到后先审核候选，再选入梗库。
4. 按你的账户实际价格填写人民币费率。**费率默认留空，不把未知价格当作零。**缺费率或响应缺用量的请求标为“待计价”，这部分不能纳入预算提醒。
5. 打开 B站直播，点击“开始观赛 → 选择窗口”。保持播放窗口展开；最小化、遮挡、转播布局、缩放和弹幕覆盖都可能影响采集或识别。
6. BP 时打开“BP 英雄选择”查看或纠正英雄，暂不分配选手；进入游戏后按计分板绑定。核对选手、队伍和版本。点击选手可纠正并锁定信息。文字或语音输入“纠正：左边上单是 TheShy，英雄是奥恩”也可提出更正。
7. 开启麦克风，讲话结束后自动识别并提问。推荐耳机，以减少解说或扬声器声音进入麦克风。也能始终使用文字输入。
8. 每局结束点击“结束本局 · 写入文档”；下一局点击“下一局”，再开始观赛。不会仅凭一个疑似结算画面自动推进局数。

采集的是**用户授权的播放窗口**，不解析 B站直播流，不上传系统声音。当前没有登录 B站、发送弹幕或发帖功能。

### v0.4：四种布局、本地匹配与纠正

- 自带 Riot Data Dragon 16.21.1 的 **173 位英雄中文名称、ID、头像及基础立绘**，运行时不访问 OP.GG 或下载图库。图库版本不是赛事版本，战术建议仍需核对比赛版本。素材来源与权利说明见 [第三方组件](docs/THIRD_PARTY.md)。
- BP 使用本地原画特征匹配，兼容放大、裁切与翻转；不把选手名或图片编号当英雄答案。完整 BP 阵容可帮助局内消除歧义，最后一个被遮挡的位置可由同队其余四人排除确认，证据中明确标注。
- 默认开启 LPL 固定布局识别：对线计分板和团战底部横排自动切换；局内识别英雄、ID、KDA、可读等级和死亡倒计时，右上击杀栏只采用可信的英雄受害者，不把水晶当选手。
- 建议全屏播放。若有网页侧栏、标题、黑边干扰，点击“自动识别 → 调整比赛区域”，框选完整 16:9 转播画面。不要只框英雄栏。首次初始化图库和 OCR 约需十秒，具体取决于设备。
- 团战横排按蓝方辅助/ADC/中单/打野/上单、红方上单/打野/中单/ADC/辅助映射。对线计分板按两列上单至辅助映射。这里只适配所提供的 LPL 布局，其他转播可使用下方备用手动校准。
- BP 单独保存展示位上的英雄，连续两次匹配才接受；不会把 BP 展示位当作选手位置。静态图无法还原真实选取顺序，当前顺序由用户确认。打开“查看 / 纠正”可从规范图库选择英雄和第几选；手工结果锁定。进游戏后才绑定到选手。
- 选手栏可点击纠正姓名、英雄并锁定，后续自动识别不会覆盖。低置信度留空，遮挡时沿用本局已确认英雄；不强猜。新一局清除本局视觉缓存。
- 自动模式每 500ms 尝试采样，忙时跳过，不排队。明确头像死亡仍即时触发；单独的 KDA 死亡增长需连续两次读取确认。击杀栏只使用右侧受害者，明确存活或英雄绑定不唯一时不据此触发。回放和首次接入的可见死亡仍允许；同一选手五秒内最多一次，冷却内信号丢弃，后到的同次死亡计数不补播。
- 无计分板的广告/图表画面保留已有数据，仅读取时钟和右上击杀栏。等级和 KDA 分开裁切，数字由字形匹配与 OCR 读取，需两次数字观测确认；死亡计时不等待战绩确认。
- 没有该选手的专属梗时，使用梗库中可见、可关闭的通用调侃；有专属梗则优先使用。搜索故障不会让死亡事件完全无话可说，个人保护和语音优先级仍生效。
- 搜索失败会显示百炼或虎扑的具体失败阶段，不影响已有本地梗库。修正配置后可重新手动搜索；没有历史搜索缓存拦截。

备用手动模式：在正常对局框选游戏时钟、彩色存活头像及可选回放标识区域。保存后只按手动校准区域检测死亡；不与自动模式重复触发。换窗口、尺寸、英雄或布局后重新校准。未启用手动模式时，上方自动模式仍工作。

本地图库、OCR 和语音均离线，不产生模型 API 费用；本地图块只在内存处理。云端默认每 10 秒发送一张背景截图，用户提问另采新截图并优先理解；选定比赛区域后，云端也使用该区域。

**验证边界**：11 张用户原图及浏览器观察画面用于像素回归（含同场顺序、遮挡与缩放检查），具体结果见 [验证记录](docs/VALIDATION.md)。特殊皮肤、遮挡、低分辨率、其他转播排版仍可能待确认或漏识别。当前主动允许回放和不同证据重复开串，减少漏报的同时会增加重复/误报机会。静态图片测试不代表整场比赛识别率，也不证明真实全链路三秒达标。

### 超时与请求失败排查

- 每次云端视觉请求发送一张 JPEG 截图（宽度不超过1440px，质量0.78），不是视频流接口。默认背景间隔10000毫秒；问答额外触发新截图。慢响应不会造成周期请求堆积。
- 原版模型请求固定 25 秒超时；现在默认为 60 秒，可在设置中调为 5～120 秒。百炼联网检索也使用该超时；单个虎扑公开页面最多等 15 秒。更长超时只是避免提前取消，不代表识别变快。降低频率也不能缩短单次响应。
- 视觉失败后等待 5、10、20、40、60 秒再尝试新截图；HTTP 400/401/402/403/404 停止本次运行的自动视觉请求，修正配置后暂停并重新开始。问答仍可使用。
- 错误标注画面识别、战术问答、语音识别或联网搜索，已知错误码给出对应说明，不回显服务商可能含敏感信息的原始错误正文。
- BP 提示词优先读取转播边缘面板，即使中央展示选手镜头；紧凑输出减少无用描述。仍可能错认名单和英雄，需手动核对。
- 默认周期请求最多约360次/小时；问答、搜梗与ASR另计。死亡使用独立本地链路，速度不依赖背景识别间隔。

切换供应商时，当前问答、视觉、语音识别共用一个 Base URL 和密钥。腾讯 TokenHub、火山方舟虽然提供兼容的图片理解 API，但其模型、JSON 输出和语音协议仍需分别验证；不要把更换 Base URL 当作全部功能已适配。

## 已实现的行为

| 场景 | 规则 |
| --- | --- |
| 正经问答 | 完整文字分析 + 简短语音结论；历史检索带出处，不混淆比赛胜率和对线指标 |
| 单人死亡 | 自动头像死亡、KDA增长或击杀栏立即触发；手动模式匹配灰头像可触发，不强求倒计时 |
| 多人死亡 | 同一识别批次短窗口聚合，选一名有可用梗的高优先级选手，再接一句团队梗 |
| 主队保护 | 个人和团队开关独立；保护只限制玩梗，不删减问答中的阵容信息 |
| 选手排序 | 已知明星的初始优先级 + 手动调整；没有梗的选手不凭空制造“热梗” |
| 回放 | 允许开串；每段可见死亡可再次触发，同一静止画面不刷屏 |
| 语音竞争 | 用户说话可打断；正经回答优先；过时的梗只保留文字 |
| 弹幕延伸 | 从可见画面提取，异步生成；仍及时的可播，迟到的只保留文字 |
| BO5 | 一个 Markdown，每局十行；支持读取前局坦克转剑姬的变化梗 |
| 预算 | 近 60 分钟滚动估算，默认 5 元弹窗提醒；用户决定是否暂停 |
| 暂停 | 停止采集、麦克风、语音及新请求，取消未完成请求，丢弃迟到内容 |

语音的“仍及时”在 v0.1 中默认为死亡证据采集后的 8 秒内；现场生成的弹幕梗需在 5 秒内返回才进入语音队列。问答期间只保留最新一组待播梗。参数暂为内部实现常量，后续可根据试用调整。

## 梗库与系列赛文档

梗库格式参见 [memes.example.md](resources/memes.example.md)：

```markdown
## 选手: TheShy
- 下雨了。
- 送姜。

## 队伍: *
- 都发狂了。
- 干燥，不亏。
```

搜梗只由用户点击触发：在“搜索梗库”里选择选手，可补充 ID，保护选手默认不选，明星选手默认重点搜索。搜索选择不更改盾牌。每名普通选手最多 2 次检索、读取 4 页、提交 60 条评论；重点搜索翻倍，每人最多返回 6 条候选，不够不凑数。不同选手复用同帖缓存。

候选保留播报句、原文摘录、解释、评论标识、来源、点赞、日期与适用条件。**候选未经选入绝不自动播报。**“中路阵亡”“敌方奎桑提参与击杀”等条件当前无可靠证据，相关候选即使入库也不自动播报；不会额外发现场付费请求判断。编辑时可确认适用条件，原文证据保留；涉及未支持的场景仍不会自动播报。

“已入库”支持按选手筛选、手动添加、编辑、启停和删除。“已删除”可撤销；删除记录保留去重标识，重启不补回内置梗，搜索和 Markdown 导入也不补回同一句。删除或停用同步撤下待播语音。换局、重启、名单更新都不自动搜索；已有梗也可再次手动更新候选。

读取范围是虎扑公开讨论帖、热门回复与可见评论，不包含全部楼层。评分讨论帖可用；只有 App 跳转或未验证过的 HTTPS 评分结构时显示“评分页未读取”，不冒充评分热评。录像请把截止日期设为比赛开始前一天；未知日期或晚于截止日期的材料不进入候选。

名字与名单匹配时忽略大小写、空格及部分分隔符。标题之外的说明不当作指令执行。导入时合并去重，不删除现有梗。

系列赛文档保存到应用数据目录的 `series/<系列赛ID>.md`。每局保存覆盖同一小节，下一局追加到同一文件；用户可编辑文档，下一局会重新读取。英雄选择仅描述本局角色，不形成“这人一直爱送”的长期人格记忆。

## 数据、密钥与费用

应用数据在 Windows 用户的应用数据目录内，可从“系列赛”或“设置”打开：

- `settings.json`：配置；密钥使用 Electron `safeStorage` 调用系统凭据加密后保存，不返回渲染进程。
- `session.json`：当前系列赛及文字消息。
- `series/*.md`：系列赛记忆。
- `memes.json`：稳定 ID、候选审核状态、梗及来源证据、启停状态和删除记录。
- `usage.json`：服务返回的 token、秒数和按已配费率估算的费用。
- `audio/*.wav`：本地生成的语音缓存。

原始比赛截图、麦克风录音不写入应用数据目录。使用云端功能时，对应截图、录音片段、对话、当前阵容、系列赛文档会发送给配置的服务；搜索会发送选手名或问题。页面和弹幕内容被视为资料，不授予工具执行权限。

搜梗 Token 使用独立费率，不沿用旧博查价格。搜索工具与模型 Token 分列费用记录；百炼返回的搜索 `count` 是意图次数，不能当作已完成或账单次数，因此工具金额仅是估算，实际用量标为待核对。未知用量不会在界面显示为零。

预算弹窗是**提醒**。不点击暂停会继续产生费用；网络中断或取消后的服务端费用可能未知。费率、阶梯定价、免费额度与退款以服务商账单为准。

“导出测试记录”只导出运行版本、请求用量、事件类型、时间和延迟，不导出密钥、截图、录音或问答正文。导出前仍应确认是否希望分享事件时间和模型名称。

## 当前限制与下一轮测试

- **尚无整场赛事准确率、延迟、费用实测。**原图回归、单次服务诊断、演示与模拟服务测试不能替代真实直播验证。
- 死亡走本地图像匹配和 OCR，证据识别出来即触发并使用预缓存语音；云端每10秒更新背景。慢识别结果与选手栏统一接受15秒内结果；设备、OCR耗时和播放状态影响延迟，当前不保证三秒。
- 本地识别固定 LPL 布局的英雄和计分板；战术理解仍用云端模型。不能识别所有排版或遮挡头像，低置信度留待确认，用户可纠正。
- 团战聚合是短批次窗口，不是完整团战分段。连续多波死亡、慢回放和不显示计时器的转播需要实测。
- B站弹幕目前通过共享画面读取，不能等同于完整弹幕流；关闭弹幕或缩小窗口后可能读不到。
- 虎扑可见评论不等于全部评论或评分热评。页面结构变化、403/405、登录限制与搜索覆盖不足会导致少候选；模型可能误解对象或笑点，必须由用户审核。
- OP.GG 历史信息优先通过站点限定搜索查找，没有完整的职业选手交手数据库。OP.GG 官方 MCP 文档当前列出的电竞工具主要是赛程和排名，不能把这些当作完整的中单交手统计。查不到时必须承认缺失。
- 防剧透使用历史日期检索范围和模型指令隔离，无法保证第三方搜索错误日期、直播自带剧透弹幕等永不泄露信息。
- 本地 Windows 音色可稳定提供语音，但情绪、停顿和真人感仍待你体验；不包含真人音色复刻。

测试方法见 [TESTING.md](docs/TESTING.md)，模块说明见 [ARCHITECTURE.md](docs/ARCHITECTURE.md)。
